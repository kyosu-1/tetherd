# v1.0: 誰の Mac にも入り、使っていないときは root が居ない Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `HOMEBREW_DEVELOPER` を設定している開発者でも `brew install` でき、tetherd を使っていない間は root のプロセスが 1 つも残らない状態にすること。

**Architecture:** v0.4 で配布経路は通った（e2e 32〜38 実機検証済み）。v1.0 が直すのは、その経路に残った 2 つの穴 — **cask が一部の利用者に対して既に壊れている**ことと、**root デーモンが常駐している**こと。どちらも v0.4 が意図的に、または知らずに残したもので、原因は実測済み。

**Tech Stack:** Homebrew cask の `postflight_steps`、launchd のソケットアクティベーション（`launch_activate_socket()` を `purego` 経由）。**この計画は依存を 1 つ追加する**（`purego`。Task 2 のみ）。

**Spec:** `docs/specs/2026-09-12-v1-macos-design.md`（§8 配布とインストール、§12 検証）

## 優先順位の根拠（すべて 2026-09-13 に実測）

v0.4 のリリース直後に実機で測って分かったことが、優先順位を決めている。**推測ではないので、実装者はこれを再導出しなくてよい。ただし信じる前に自分で確かめること** — この 2 つの機構は、今日それぞれ 1 回ずつコントローラの誤りで壊れている。

### なぜ Task 1 が最優先か: cask は今すでに一部の利用者に対して壊れている

3 つの事実が重なっている。

**(a) quarantine の除去は必須。飾りではない。** 測定手順と結果: `Caskroom` のバイナリをコピーし `xattr -w com.apple.quarantine ...` を付けて実行したら、**Gatekeeper がモーダルダイアログ（「Apple は "tetherd-q" に…マルウェアが含まれていないことを検証できませんでした」）でプロセスを止めた**。CLI バイナリなら Gatekeeper は素通りするのではないかと考えて測ったが、止まった。Homebrew は cask のダウンロードに必ず quarantine を付ける（`Library/Homebrew/cask/download.rb:256` の `Quarantine.cask!`）ので、**`postflight` の `xattr -dr` が無いと tetherd は起動しない**。formula にこの口が無いことが cask を選んだ唯一の理由。

**(b) その `postflight` が非推奨になった。**

```ruby
# $(brew --repository)/Library/Homebrew/cask/dsl.rb:861
odeprecated "`#{dsl_key}`", "`#{dsl_key}_steps`"
```

`preflight` / `postflight` / `uninstall_preflight` / `uninstall_postflight` の 4 つが `*_steps` に置き換わった。

**(c) そして一部の利用者には警告ではなく例外になる。**

```ruby
# $(brew --repository)/Library/Homebrew/utils/output.rb:157-233
def odeprecated(method, replacement = nil, disable: false, disable_on: nil,
                disable_for_developers: true, ...)
  ...
  disable = true if disable_for_developers && Homebrew::EnvConfig.developer?
  if disable || Homebrew.raise_deprecation_exceptions?
    raise MethodDeprecatedError.new(message)
```

`disable_for_developers` の既定が `true` で、dsl.rb:861 はそれを上書きしていない。つまり **`HOMEBREW_DEVELOPER` を設定している人の `brew install` は例外で失敗する**。tetherd の利用者層はまさに開発者なので、これは狭いケースではない。**検証機（`HOMEBREW_DEVELOPER` 未設定）では警告で済むため、v0.4 の e2e では素通りした。**

**(d) GoReleaser のバージョンを上げても直らない。** `main` ブランチの cask テンプレートも `postflight do` を吐く（実測: `internal/pipe/cask/templates/cask.rb` に `postflight_steps` / `install_steps` の記述が無い）。v2.19.0 の nightly が存在するが、テンプレートは変わっていない。**だから自分で回避する必要がある。**

**(e) 回避は表現可能。** `postflight_steps` は宣言的 DSL だが、任意コマンドを実行する `run` ステップがある:

```ruby
# $(brew --repository)/Library/Homebrew/install_steps.rb:715
def run(command, args: [], base: nil, env: {}, sudo: false, must_succeed: true, ...)
```

そして GoReleaser の cask には **`custom_block`** があり、`cask "name" do` の直後に任意の Ruby を差し込める（実測: テンプレートの `{{- with .CustomBlock -}}` が最初のブロック）。

### なぜ Task 2 が次か: 設計上の負債で、動作はする

spec §8 は **helper を常駐させない**設計を選んでいる。launchd が `/var/run/tetherd.sock` を保持し、最初の接続で helper を root で起動し、接続が無くなって 30 秒でアイドル終了する。v0.4 はこれを実装せず `RunAtLoad: true` の常駐にした（Ruling S）。

**代償は攻撃面。** 常駐だと root で待ち受けるプロセスが 24 時間存在する。アクティベーションなら tetherd を使っている数分間だけ存在する。**動作はするので Task 1 より後**だが、spec が意図的に選んだ設計であり、README と spec に「v0.4 は常駐」と明記してある約束でもある。

**後から入れるのが安いことは実証済み。** plist を書くのは `sudo tetherd-helper install` 自身で、それは e2e 37 行で冪等性を検証済み。利用者がすることは**既に打つよう案内されているコマンドをもう一度打つだけ**。

### Task 2: ソケットアクティベーション（**この計画で唯一 `go.mod` を変える**）

**Files:**
- Create: `internal/helper/activation_darwin.go`, `internal/helper/activation_test.go`
- Modify: `go.mod` / `go.sum`, `internal/helper/daemon.go`, `internal/helper/server.go`, `cmd/tetherd-helper/main.go`, `docs/install.md`, spec §8

**Interfaces:**
- Produces: `Sockets` を持つ plist と、launchd から listener を受け取って 30 秒アイドルで終了する helper

**spec §8 が指定していること（これが要求仕様）:**

> **helper は常駐しない。** plist の `Sockets` で launchd が `/var/run/tetherd.sock` を保持し、最初の接続で helper を root で起動する（ソケットアクティベーション。`launch_activate_socket()` は cgo を使わず `purego` で呼ぶ）。helper は接続が無くなって 30 秒でアイドル終了する。`KeepAlive: {SuccessfulExit: false}` で、クラッシュ時だけ launchd が再起動

**設計上の決定:**

1. **`purego` で `launch_activate_socket()` を呼ぶ。** cgo を使わない（`CGO_ENABLED=0` でクロスコンパイルしている前提を壊さない）。
2. **`KeepAlive: {SuccessfulExit: false}` はそのまま。** v0.4 で `man launchd.plist` を実測した結果、これは「終了コードが 0 以外なら再起動」。**アイドル終了が終了コード 0 になるので、この形がはじめて正しくなる** — v0.4 では初期化失敗が無限再試行される形だった。**その記述を spec §8 から直すこと。**
3. **`RunAtLoad` を落とす。** `KeepAlive` は `RunAtLoad` を含意する（同 man: "implicitly implies RunAtLoad"）ので、**`KeepAlive` を残したまま `Sockets` を足すだけでは常駐が消えない可能性がある。実測して判断し、根拠を報告に書くこと。**
4. **30 秒のアイドル終了は注入可能な時間にする。** テストで待てない。
5. **`ClearLeftovers` の位置を確認する。** helper は起動のたびに残留 pf アンカーと resolver を掃除してから listen する（spec §8）。**起動が頻繁になるので、この掃除が実行中の別セッションを壊さないか**を確かめること。**これは常駐では起きなかった問題で、この計画で最も見落としやすい。**

- [ ] **Step 1: `purego` で `launch_activate_socket` を呼べることを最小の実験で確かめる**

**まずここで止まる可能性を潰す。** `purego.Dlopen` / `RegisterLibFunc` でシンボルが引けるか、返り値（`int32`、`*int32` の fd 配列、`size_t` の個数）をどう受けるかを、**小さな単体プログラムで実測**する。launchd 配下でないと `ESRCH` が返るはずなので、**「呼べた」の判定を「成功した」ではなく「期待したエラーコードが返った」に置くこと。**

Expected: シンボルが引けて、非 launchd 環境で `ESRCH`（3）が返る。**引けなければここで報告して止まること** — 代替（cgo を許す / `purego` をやめる）は計画の変更であり、実装者の裁量を超える。

- [ ] **Step 2〜4: fd → `net.Listener` の経路と、注入可能な継ぎ目**

要求:
- **fd の出どころを注入できること。** 実 launchd 無しでテストするには、`socketpair(2)` や `net.Listen` で作った fd を「launchd が渡した fd」として与えられる必要がある。
- **継承した listener を使うとき、helper は自分でソケットを作らない**（launchd が持っているので `bind` が衝突する）。
- **継承が無いとき（前面起動、`hack/e2e-local.sh`）は今の経路のまま動くこと。** これは v0.2b から動いている検証用の経路で、壊すと開発ループが止まる。
- **mutation: 継承した fd を使わず自分で bind する / 継承の有無の判定を反転させる / fd を閉じ忘れる。**

- [ ] **Step 5: アイドル終了**

要求:
- 接続が無くなって指定時間で `Serve` が戻り、終了コード **0** で終わること（`KeepAlive: {SuccessfulExit: false}` が再起動しない条件）。
- **接続がある間は終了しないこと。** `tetherd run` は数時間続きうる。
- **終了時に `Shutdown` が走ること**（pf と `/etc/resolver` の片付け）。v0.4 で確認済みのこの経路を壊さない。
- **mutation: 接続中でも終了する / 終了コードを 1 にする / `Shutdown` を飛ばす。**

- [ ] **Step 6: plist**

`Sockets` を足し、`RunAtLoad` を（Step 3 の決定に従って）落とす。**`Plist` は純粋関数のまま**（v0.4 の形）。mutation: `Sockets` のキー名を間違える / `SockPathMode` を落とす。

- [ ] **Step 7: spec §8 と `docs/install.md` を「常駐しない」に戻す。** v0.4 が書いた「v0.4 では常駐する」という記述と、`KeepAlive` の解釈（決定 2）を両方直す。**README の「The root helper stays resident」も消すこと** — 消し忘れると v0.4 が 4 件出した「別の場所に落ちた修正から取り残された古い記述」と同じになる。

- [ ] **Step 8: コミット**（`purego` の追加、helper の経路、plist、ドキュメントを**別コミット**に）
